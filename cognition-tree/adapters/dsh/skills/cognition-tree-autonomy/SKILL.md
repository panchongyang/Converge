# 在当前回合发现认知树

只处理当前回合中值得长期追踪的判断、依据和取舍。例如，人确认一个决定、要求记下、切换话题或完成一个阶段时，看看是否形成这样的内容。临时笔记、一次性操作和没有实质变化的对话不用建树或写树。不开后台、定时或无人值守任务，不扫描旧会话，不在结束会话时补交。

## 先找，再决定是否建树

1. 用 `cognition_tree_list_trees({limit?, after?})` 分页查看当前工作区可读的未归档树。`limit` 为 1–100 的整数（默认 25），需要续读时把返回的 `nextAfter` 原样传给 `after`，缺少 `nextAfter` 表示到末页。目录行给出 `treeId` 和 `rootQuestion`。一页未命中不代表没有候选；发现范围不足以判断是否有候选时，先问或不建。不要根据标题猜 ID，也不根据侧栏、上次操作或过程材料推断目标。
2. 找到候选，用正常的 `cognition_tree_read_view` 显式传入目录给出的 `treeId`，核对根问题及相关判断是否适合本轮。多个候选无法辨别时询问或跳过，不为了回避选择另建一棵。如果已经拿到可靠的 `treeId`，可直接读树核对。
3. 确认没有合适候选，且本轮有明确、持久、值得独立维护的根问题时，可用 `cognition_tree_create_tree` 自主建树。工作区已开启自主维护，常规操作不必逐棵请示；但用户当前要求不写、范围未明或持久性不清楚时，就先问或不建。创建时指定新的 `treeId` 和清晰的 `rootQuestion`；不要为每个话题建树。创建冲突或结果未知时先查树，不盲目重试。

正常读到已有树或成功创建树后，本会话可以加载随包的 `incremental-formalization` skill，按它的规则维护。它不是某棵树的专属槽位；同一对话可以维护多棵树，每次读写与过程操作都传目标 `treeId`，并在写入前重读该树。

工作区开关只委托该工作区范围内的自主维护，不提升 DSH 文件权限。工具可见、读树成功和 skill 加载不会扩大用户授权。遵守用户明确的只读、暂停和范围限制；只读时可以发现和读取，不能建树、保存过程或写树。AI 不替人确认。
