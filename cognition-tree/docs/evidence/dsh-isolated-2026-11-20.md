# DSH 接入：隔离工作区实测

档案：记录本机的证据与适用范围，不是现行安装说明。复跑入口见[插件说明](<../../adapters/dsh/README.md>)。

## 数据确实写到哪里

Windows、Node 24.22.2 自带 `node:sqlite`。测试在仓库根 `.local-work/` 内生成新的工作区，未在 Converge 正式工作区创建 T1。每棵树一个 SQLite 主库；手稿 T1 和负载树保存在两个独立主库，不从网页 localStorage 取数据。

[磁盘集成测试](<../../adapters/dsh/test/disk-load.test.ts>)用真实内核、实际手稿译本和 SQLite 写入：人侧明确自举 T1 → AI 给 T1.2.4 添加补充 → 人侧确认指定形成记录 → 关闭全部连接 → 创建新的存储实例。从同一目录按新增节点 ID 读回，原父节点、AI 执行者、当前人确认标记与确认修订 ID 均与关闭前一致。

一次隔离实测夹具（临时工作区目录，不随公开候选发布）。负载种子 JSON 为 **5,585,203 个 UTF-8 字节**，256 个子分支、255 条入边；40 次小变更穿插局部读取，限制 48 次扫描 / 8 节点 / 4,096 字节。本次最大序列化响应 2,733 字节，实库主文件 5,750,784 字节，`PRAGMA integrity_check` 为 `ok`。计时为同进程存储层的本机样本，不能当作真实 DSH 的响应时间。

[存储端口测试](<../../adapters/dsh/test/sqlite-store.test.ts>)还覆盖真实 SQLite 拒绝 `COMMIT`（延迟外键不成立）：自举和日常写入失败均不发通知，重开后的状态与版本没有半笔变更，修正输入后可重试。另以约 12.8 MB 文件、2,600 个节点和 900 条入边检查查询计划：按父节点、两端引用、时间/修订与未确认目标走索引，从续页键定位，不先全表排序再截断。

## 宿主与插件的边界

- **真实模块**：加载打包后的服务端与 worker，在本机安装的 DSH 0.2.2-rc.1 的 Cordis、工具注册表、Connection exact Fetch 注册表中装配，进程内发请求；读写走正式内核和 SQLite。安装/卸载隔离实例不会更改真实 profile。
- **控制变量**：工作区注册记录、会话持久化和主检查的 owner peer 是隔离夹具；另用真实 Connection 配合测试专用内存凭据核对 owner/非 owner、Host/Origin 行为。测试不读取个人凭据。
- **文件策略**：AI 工具写入沿用当前宿主会话的文件策略：只读、未知策略及越出工作区的写请求都在 worker 调用前被拒绝。人的 owner UI 与 AI 工具各走各的入口。
- **资源影响**：只注册认知树自己的工具和两条路由；激活与仅订阅时 worker 数为零，业务请求到来才启动，卸载后结束。后台异常只拒绝本插件请求；不重发写操作，也不改变无关工具和路由的注册。
- **客户端**：打包的 ModuleLoader 工厂复用宿主 React、JSX runtime、ReactDOM；注册主面板、侧栏、本插件两个写入工具的聊天卡与会话上下文组件。CSS 在 ShadowRoot 内，阅读与编辑热键在实际渲染根订阅。没有自动操作浏览器或把槽位注册成功冒充目视验收。

最终构建产物检查（本机原始报告未随公开候选发布）：19 项通过。进程内无关路由 p95 为基线 0.073 ms / 插件空闲 0.036 ms / 插件工作中 0.083 ms；worker 数为 0 → 0 → 1 → 0。响应采样有系统噪声，不能推出绝对零开销。卸载再挂载后，经新工作线程读回此前新增判断和修订；上个进程的折叠游标返回 `viewExpired`。

最终复跑：四个包的类型检查通过；内核 111、共享 UI 30、独立网页适配 35、DSH 适配 75，共 251 项 Vitest 通过。独立网页和 DSH 发布包均重新构建。以上没有启动任何新的 Web 服务。

**未验证：**正在使用的 DSH Web GUI、真实网络链路、模型实际发起工具调用、同机其他负载下的吞吐、真实面板排版与交互。真实 profile 安装和重启不在本次授权内。
