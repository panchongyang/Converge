# 认知树 MVP · 内核接口单（P2 草案）

## 一、目标

让人和 AI 能从一个判断读出连贯的局部树，也能直接维护这棵树、查回原判断和每次变更。**有历史的日常变更提交即生效，只有人能确认，人不必逐条审批。** 单树 5 MB、高频修订、历史持续增长是日常负载；一次变更或确认只读写相关记录，局部读取不先加载整棵树。

操作权和留痕边界以[人与 AI 操作边界决策树](<../PRINCIPLES.md#人与-ai-操作边界决策树>)为准。**下文的签名、SQLite、表结构和游标实现是待审提案。** 不引入跨进程写入协调、权限系统或灾备设计；本稿不决定 [Q5 主阅读方式](<../open-questions.md>)，也不是实现、原型改动或自举导入的授权。

## 二、流程图

```text
写：人或 AI 执行日常变更 / 人明确确认或发起自举 → 入口识别 actor → catalog 校验身份
    → 模型开启单树事务 → commands 校验目标、当前状态和参数
      ├─ 日常变更：节点或状态 + 引用 + 形成记录 → 提交即生效，未获人确认
      ├─ 确认：关联明确的变更或导入节点 + 确认记录 → 只记人确认，不改变树形或分支状态
      └─ 自举：创建初始树，保留导入来源，不生成新的人确认
    → 提交成功才返回；失败回滚，数据与日志均不动

读：起点 + 展开参数 + 预算 → 同一份已提交数据 → 按父节点、引用两端分批取行
    → 去重，补原树父链 → 有根的树视图 + 引用 + 折叠说明
    → 范围读完 / 有界续读；要求一次取全而超限则报错

读待确认：执行者种类 + 页大小 → 只含未确认节点的索引 → 每条形成记录或导入判断一项，可直接作为确认目标
```

## 三、接口单

### 3.1 判断、状态与写入

| 对象 | 含义与归属 |
| --- | --- |
| `Node {id, parentId, body, state?, origin, currentChange?, confirmation?}` | 新节点由模型分配树内唯一 ID，自举沿用原 ID；ID 稳定且不复用。根的 `parentId = null`，其余节点各有唯一父节点。保存后的 `body`（标题、判断、依据、来源）不可覆盖。`state: keep / prune / open` 表示留、剪、未决；剪除理由与复活条件随节点详情可读。`origin` 区分普通分支、补充、勘误和替代；替代另记 `replacesId` 及 `proposed / applied`（拟替代 / 已执行），与有无人确认无关。 |
| `currentChange {revisionId, by}`、`confirmation` | 前者指向该节点最近一次实际变更的形成记录，并带出执行者。`confirmation: unconfirmed / humanConfirmed` 标记当前变更是否由人确认，不表示执行者，也不决定变更是否生效。未发生日常变更的自举节点不填 `currentChange`，沿用导入的确认程度；手稿未载的分支状态或确认程度保持缺失。 |
| `Ref {id, from, kind, target}` | 三种类型：`premise / example / conflict`（依赖前提 / 同类实例 / 与事实冲突）。目标为树内 `{nodeId, part?}` 或外部 `{doc, part?}`；`part` 可指出剪除理由或文中实例，省略指整体。依赖前提指向祖先链之外；反向查找不颠倒原边。外部材料返回定位符，不展开成另一棵树。 |
| `Revision {id, kind, at, by, nodeIds, summary, detail?, source?}` | `formation` 记录一次执行，`confirmation` 记录一次人的确认。新写入的 `at` 是实际发生时刻的含时区 ISO 时间，`by` 来自可信入口，`nodeIds` 至少含一个稳定节点 ID，供历史查询。新修订有下述结构化明细；导入保留原出处与时间精度，事实不足不补造明细。 |

新的形成记录用 `detail {action, effects, reason?, reviveWhen?, previousPrune?, replacement?}` 记录实际发生的变化。`action` 是 `createTree`（新建根）、`addBranch`（新增分支）或下表中的决定名。`effects` 内每项为 `{nodeId, beforeState?, afterState}`：新节点省略 `beforeState`，原状态未载用 `null`。补充、勘误的父节点可在 `nodeIds` 中供回查，但不是 `effects`，不改变它的确认标记。剪除和替代必记剪除理由与复活条件；`replacement {oldId, newId}` 明示替代方向。重新打开的理由只写日志，不回填正文。重新启用时把当前的剪除理由与复活条件一并归入该条明细的 `previousPrune?`，包括来自手稿的内容，缺项保留缺失。确认记录的 `detail {target}` 只标明被确认的对象，不复制正文或状态。

`Draft = {body, state, refs, pruneReason?, reviveWhen?}` 只描述**新节点**，不能设置确认标记或覆盖已有数据。初始状态必传；无引用传 `[]`；若初始为剪，剪除理由和复活条件均须非空白，形成记录一并保存。`Placement` 二选一：`{parentId, kind: branch / supplement / erratum}` 指定父节点；`{replacesId}` 指定拟替代的旧节点，新节点挂在其真实父节点下。根没有同级，不可被替代。

操作统一经 `dispatch(actor, op, input) → Promise<Output[op]>`。树 ID 来自工作区所选树，节点和修订 ID 来自读结果，actor 由入口识别，不由请求自报。参数除标 `?` 外必传，无默认目标。catalog 守身份边界，commands 在写事务内校验目标、状态和参数，models 保证变更与修订同次提交。目标不存在报 `missing`；身份无权、动作不适用或参数不合规报 `invalid`；提交失败报 `storage`，不报告成功。

| 操作及返回 | 谁调用 / 输入的作用 | 成功后的含义 |
| --- | --- | --- |
| `createTree(treeId, rootQuestion) → TreeId` | 人或 AI；树 ID 与非空根问题必传，不接受节点、引用或历史。 | 在新树事务中创建唯一的根（ID 同树 ID，`open`、未确认）与 `createTree` 形成记录，已有树不得覆盖。 |
| `addBranch(treeId, placement, draft) → NodeId` | 人的详情页或 AI 工具；placement 定落点，draft 给出新判断。人侧 UI 首版只提供子判断、补充、勘误三种落点，不提供登记替代候选的入口；这是界面范围，内核对两种 actor 的规则相同。 | 分配新 ID，节点提交即存在。登记同级候选不剪旧节点；须显式执行替代。 |
| `decideNode(treeId, nodeId, decision) → NodeId` | 人的详情页或 AI 工具；nodeId 指被操作的节点，decision 是下表的一项。 | 执行日常变更，返回被操作节点的原 ID；记形成，不自动确认。 |
| `confirm(treeId, target: ConfirmTarget) → RevisionId` | **仅人**；target 是明确展示、由人确认的变更或自举判断，取自 `readNode` 带回的当前变更或 `readUnconfirmed` 的一项。 | 返回新确认记录 ID。只记人确认，不增节点、不改分支状态、不执行替代。 |
| `readView(treeId, focus, expand, budget, onLimit, cursor?) → TreeView` | 人或 AI；focus 是节点 ID 或显式选择树根。 | 各参数、完整性和续读见 3.2；不写时间线。 |
| `readNode(treeId, nodeId) → NodeDetail` | 人或 AI；nodeId 指要读的判断。 | 取指定节点的正文、状态、确认信息，以及 `currentChange` 所指那条形成记录的全文，人在确认前据此看清这次变更做了什么；没有日常变更的导入判断不带这一项。邻居用 `readView`，其余历史用 `readHistory`。 |
| `readHistory(treeId, {nodeId?, limit, after?}) → Page<Revision>` | 人或 AI；limit 是页条数，after 是上一页末项。 | 按关联 ID 查节点历史；不传 nodeId 按树查，不传 after 从最近一页开始。 |
| `readUnconfirmed(treeId, {by, limit, after?}) → Page<PendingTarget>` | 人或 AI；by 是要列出的执行者种类，limit 是页条数，after 是上一页末项。人侧 UI 的待确认列表传 `by: [ai, import]`，人自己执行的变更不列入。 | 列出尚无人确认的目标，每项都可直接交给 `confirm`；各项的定义与顺序见下文“确认如何绑定”。只按未确认索引分页，不扫描全表，不做全量计数。 |
| `bootstrapTree(seed: SeedTree) → TreeId` | 供显式的隔离样例与历史种子使用，非工作区建树入口；DSH 不向人侧路由或 AI 工具开放该操作。 | 一次提交创建目标树。已存在报 `invalid`，不覆盖；导入不是确认。详见 3.4。 |

**`decideNode` 的决定。** `decision.type` 为下表动作名，其余字段为参数。`reason` 是调用方给出的非空白理由；`reviveWhen` 是非空白复活条件；`state` 是调用方明确选择的目标状态。均无缺省。

| 决定 | 适用条件与实际变更 |
| --- | --- |
| `prune(reason, reviveWhen)` | 非根且尚未剪除；记为剪，保留原节点和引用。 |
| `revive(state, reason)` | 只对已剪节点；恢复为 `keep` 或 `open`，保留剪除历史。 |
| `setOpenOrKeep(state, reason)` | 只允许 `open → keep`、`keep → open`，或把分支状态未载的判断定为 `keep` 或 `open`；根和待执行的替代候选不适用。不增节点、不改正文、父子关系或引用。 |
| `applyReplacement(reason, reviveWhen)` | nodeId 指未被剪、尚未执行的替代候选，其对应旧判断仍未被剪，且两者同父。一次提交：标候选为 `applied`、剪掉旧判断，记录新旧 ID。`effects` 同时列出旧判断（转为剪）和候选（分支状态前后相同，来历转为已执行），两者的 `currentChange` 都指向这条记录。旧原文与引用不动；不需要人的确认来执行。 |

**确认如何绑定。** 日常提交将 `effects` 中节点的 `currentChange` 指向本次形成记录，`confirmation` 设为 `unconfirmed`。这对人、AI 都适用；谁执行与谁确认分别记录。人自己执行的变更同样未确认，需要时另做一次 `confirm`；不提供把执行与确认合成一步的操作。树里原来有的人确认留在历史，不用于给新变更背书。

`ConfirmTarget` 二选一：`{revisionId}` 指读到的形成记录，`{seedNodeId}` 指尚无日常变更的导入判断。确认形成记录时，事务内核对它仍是至少一个实际受影响节点的 `currentChange`；只更新指针仍指向它的节点，不能误标后续变更。确认替代针对执行替代的那条记录，旧判断和候选只要仍指向它就一并标记；不能靠确认候选触发替代。对自举判断，仅当它仍无 `currentChange` 才能确认导入时的状态。失效或重复确认报 `invalid`，不写日志。所有写入只走有修订记录的操作；不提供裸写状态、覆盖正文或跳过日志的入口。

`PendingTarget` 是 `readUnconfirmed` 返回的一项，二选一：`{revisionId, at, by, summary, nodeIds}` 是尚未确认、且仍是至少一个节点 `currentChange` 的形成记录，`nodeIds` 只列仍指向它的节点；`{seedNodeId, title}` 是没有日常变更、导入时确认程度为 `unconfirmed` 的判断，确认程度缺失的不列。参数 `by` 是执行者种类的非空子集：`human`、`ai` 按形成记录的执行者筛选，`import` 选导入判断；没有缺省。形成记录按 `(at, revisionId)` 从新到旧，导入判断排在其后、按节点 ID 排列；`after` 传上一页末项对应的 `ConfirmTarget`（`{revisionId}` 或 `{seedNodeId}`）。一项被确认后，或它涉及的节点都有了后续变更后，就不再出现。

### 3.2 从整棵树折出一部分：参数、结果、成本

展开范围由 UI 或 AI 工具显式传入，不暗中套一个“全部”默认值。深度和跳数的单位是边数。

| `expand` 参数 | 语义 |
| --- | --- |
| `subtreeDepth` | 初始焦点向下的树深；0 只命中焦点，1 加直接子节点。可显式请求直到叶子，仍受预算约束。 |
| `jumpHops` | 一条路径最多跨多少条树内引用边，非负整数；0 为纯子树。沿树向下、补父链都不耗引用跳数。 |
| `direction` | `out`：我指向谁；`in`：谁指向我；`both`：两个方向都查。无论从哪头读，返回原方向和类型。 |
| `jumpFrom` | `anchor` 仅从本轮起点跳；`expanded` 可从本轮起点及其按深度展开的子节点跳。首轮起点为焦点，下一轮起点为每个引用落点。 |
| `afterJumpDepth` | **每次**落点再向下展开的深度；0 只命中落点。与 subtreeDepth 同单位，独立生效。补进视图的连接祖先不是新的起跳点。 |

**结果是一棵树，不是遍历路径列表。** 拟返回 `TreeView {rootId, focusId, nodes, refs, boundaries, complete, stamp, cursor?}`。nodes 是可绘制的节点行（ID、真实父 ID、标题、分支状态、`currentChange`、`confirmation`、命中或仅连接）；执行者和确认分别可读，长正文按需取。每次成功返回包含原根、焦点及连接所需的父链；剪枝、未确认不让结构断开。树内引用两端都能定位，外部引用返回出处。节点按稳定 ID 去重，引用按边 ID 去重：两个不同的引用碰到同一节点，仍是两条边。遇环不反复走相同的展开状态；若同一节点通过另一条路径获得更多剩余深度或跳数，仍补足未覆盖的范围。

例如原树有 `R→A→C` 和 `R→B→Y` 两段父子链；C 是勘误，引用为 `C→Y`，Y 又引用 Z。以下读法命中 A、C、Y；R、B 只为还原父链。Y 仍在 B 下，既不挂到 C 下，也不带出 Z 或 B 的其他孩子。只把 jumpFrom 改成 anchor，A 自身没有出边，本次就不会命中 Y。

```json
{"subtreeDepth":1,"jumpHops":1,"direction":"out","jumpFrom":"expanded","afterJumpDepth":0}
```

**范围不等于预算。** 一跳可能有十万条入边。拟由调用方传 `budget {maxScans, maxNodes, maxBytes}`：依次约束本次实际检查的邻接行和查找、返回节点数、序列化响应字节（含引用和折叠标记）。正有限值，不接受“无限预算”；具体数值留给负载实测。先按索引游标分批取相邻项，再扩展；空查、重复命中、向前探一条、连接父链也计费。不能先取出全部入边再去重、排序、截断；按稳定键顺序推进，不为显示“还有多少”做全量计数。遍历不读长正文；取节点行时先核对需要返回的大小。本契约约束操作量与输出量，不承诺与磁盘、缓存或树高无关的固定毫秒数。

| 读到的边界 | 返回约定 |
| --- | --- |
| 参数范围到此 / 已查尽 | 到深度、跳数或方向边界标 `scope`，表示没要求查；在范围内确实查尽标 `exhausted`。AI 视图的 `jumpHops=0` 已表明没查询引用，不逐节点输出 `refs/scope`，也不把预算截断标在引用轴；人侧仍保留逐节点提示。`complete` 指累计是否覆盖请求范围，不是本页是否含整棵树。每一页都须是连通树，按实际输出的 UTF-8 字节计费（内核默认 JSON；有界的 AI 模型表示可注入精确度量，不改变操作契约）。 |
| 预算先到，`onLimit=fold` | 只发已经连回原树的部分，在尚未完成的遍历位置标 `budget`，`complete=false`、附续读游标。不为每个没看的邻居造占位；计入标记自身的开销。没有容得下焦点及父链的预算，或一项也无法继续推进，明确报 `rangeTooLarge`，不发断树或空转游标。 |
| 预算先到，`onLimit=exact` | 报 `rangeTooLarge`，不以部分结果作成功响应，不在后台悄悄读全。 |

遍历或投影超限时，`rangeTooLarge` 指出已经碰到的预算项。在本次已读结果足以确定输出字节下界时，说明至少需要多少 UTF-8 字节；下界可能小于读完所需预算，也不额外扫描来估算。

每次读基于同一已提交版本（stamp）。续读用同一查询和版本的游标，保存遍历位置、已展开状态和待连回的路径；每批本身仍成树，调用方按 ID 合并。实现提案是只在连续读取期间短暂保留读快照，读完、取消或到期即释放；若游标到期，明确报 `viewExpired`，可从折叠点发起新读，不把两个版本拼成一个。第一次调用不传 cursor；续读仍有独立预算。

### 3.3 增量持久化与四个端口（提案）

**每树一个 SQLite 主库**，例如工作区 `.converge/T1.sqlite`。业务数据共用同一事务；SQLite 的事务辅助文件不是第二份业务日志。选它是因为查询可从关系两端走索引、提交只动相关行和索引页，不要求每次解析或重写整树。代价是主库不能像文本一样直接阅读或看 Git 行差异。以下是表的职责，不是已批准的建表语句：

| 存什么 | 怎样服务实际读写 |
| --- | --- |
| `tree_meta`、`nodes` | 记树 ID、根、提交版本；按节点 ID 定位，按 `(parent_id, id)` 顺序取孩子。节点行保存当前状态、当前形成记录 ID、确认标记和替代来历；按修订 ID 取当前执行者，不重放历史。未确认的节点另有一个部分索引，供 `readUnconfirmed` 分页：有日常变更的按执行者种类、变更时间和修订 ID 排列，导入判断按节点 ID 排列；与节点行同笔更新。勘误只插入新节点及关联，不重写父正文。 |
| `refs` | 每条边一行。`(from_id, id)` 和 `(to_node_id, id)` 分别支持出、入向游标读取；指向材料的边保留 doc/part，不伪造目标节点。 |
| `revisions`、`revision_nodes` | 追加修订、结构化明细和关联节点。按 `(at, revision_id)` 翻树时间线，按 `(node_id, at, revision_id)` 定位节点历史；用修订 ID 取确认目标，用目标键检查重复确认。一笔事务写相关节点、当前变更指针、确认标记、日志、关联和提交版本，不改写旧记录。 |

| 端口（拟签名） | 参数来源、调用点与完成条件 |
| --- | --- |
| `TreeStore.openRead(treeId) → Promise<ReadSnapshot>`；`TreeStore.transact(treeId, mode, work) → Promise<T>` | 由模型调用，适配器绑定工作区。ReadSnapshot 提供版本、按 ID 查节点行、按父节点、引用端点、时间键或未确认索引分批读以及 close；分页给起点键与剩余额度，不接受裸 SQL。mode 为 `existing` 或新树专用的 `createNew`（空白建树或受限种子初始化）；work 在同一单树事务按 ID 读取相关节点和目标修订，按确认目标查重，写入明示变更并追加修订；提交后才兑现结果，失败回滚。 |
| `Clock.now() → Instant` | 模型每次产生新日志的命令取一次含时区时刻，同笔记录共享它。无参数；导入历史不调用它伪造精确时间。 |
| `CognitionClient.call(op, input) → Promise<Output[op]>` | 共用 UI 传当前树、目标及读写意图，不传 actor。确认须来自人的明确操作；AI 工具和模拟器走各自 AI 入口，只能读和执行日常变更。两侧复用 catalog 和同一内核语义。 |
| `HostBridge.openSource?(target: {doc, part?}) → Promise<void>` | 人打开外部依据时调用，目标来自引用；part 缺省指整份材料。宿主无导航能力时显示出处文本，导航失败不影响树数据。 |

引擎与索引属于存储适配器；queries 决定遍历、去重和树形投影，commands 决定可接受的判断变化。DSH 文件库可使用 WAL 让短读与修订并行，不让闲置视图无限期占着快照。独立网页使用隔离的事务存储或测试替身，不把内存测试当作 SQLite 性能证据。业务错误区分 `missing`、`invalid`、`storage` 和 3.2 的两种读取结果错误；失败不报告已保存。不建设锁服务或通用版本回放系统。

### 3.4 T1 一次性自举

取[手工树](<../../../认知树.md>)的概览确定父子关系，以稳定 ID 对齐节点正文，保留依据、留剪、确认来源、引用目标和原形成记录。`SeedTree` 是一次导入的输入，不是日常读写单位。只在目标树不存在时一次事务创建；之后以产品数据为准，保留手稿，不回写、不双向同步。

历史按原行序保留行号、叙述及可知的时间精度；只有日期就按日展示，不补午夜或导入时刻。混合记录可分别标形成/确认，共用原出处。#8 的确认关联 T1.2.2、T1.2.3、T1.2.5、T1.3.3.1、T1.3.3.2，不含仍未决的 T1.2.4。T1.3.1 缺少复活条件就保留缺项，不为导入编理由。

| `adapters/dsh, adapters/browser` | 可信入口区分人和 AI，对接事务存储、索引读取、时钟和自举翻译；不从输入采信身份，不另解释树语义。 |

## 五、验收：人的使用效果与工程证据分开

| 使用效果（人看） | 实现阶段应取得的证据 |
| --- | --- |
| 人和 AI 写勘误都只添子节点。AI 执行替代后，旧枝当即被剪，新旧关系可查，但不显示人已确认；旧引用点开的仍是原话。 | 两种 actor 均可新增和执行替代；覆盖正文的请求无可用操作。确认候选不触发替代。注入替代提交失败再开库，新旧状态、确认标记和日志均不半生效。 |
| AI 可以直接剪除、重新启用、切换「留 ↔ 未决」，或为状态未载的判断定下留或未决；不用等人，理由和原先的人确认仍可查。 | 两种 actor 的合法日常操作均生效；核对稳定 ID、原文、引用、当前变更指针及一条结构化形成记录。验证空白理由和不适用状态被拒；失败时状态、标记和修订均不变。 |
| 人只在需要时确认指定变更；确认前能看到这次变更做了什么；确认不改变分支状态，也不会把后来的 AI 变更误标为人确认。 | AI 调用 `confirm` 或自报 `human` 均不能获得确认。核对 `readNode` 带回的当前变更就是确认目标。验证人确认只追加确认记录并更新对应标记；确认执行替代的记录时旧判断和候选一并标记。验证重复确认、失效目标、替代一侧已发生新变更的情形，后续变更不被误标。 |
| 人能看到还有哪些 AI 变更和导入判断没有确认；树很大、变更很多时也能分页列出。 | 在 5 MB 库中混入大量已确认和人执行的变更，按执行者种类分页读取：每页的扫描量随页大小增长，不随树的大小增长，不全表扫描、不全量计数；同一修订不重复出现；确认或后续变更之后，对应目标从结果中消失。 |
| 从 A 看到另一支的 Y，还看得出 Y 属于 B。反向读、循环或多条引用均不复制节点。 | 用 3.2 的例子切换起跳范围、方向、跳数、跳后深度与零深度；核对父链、边的原方向、去重、同一 ID 以不同剩余深度到达时的完整性。 |
| 大扇出时仍是一棵可读的树，知道哪里因参数折叠、哪里还可续、哪里确实没有。 | 用高入度、重边命中、长父链分别触发扫描/节点/字节预算。记录实际读取条目和输出大小；检查 exact 超限、游标续读/失效和页间并发修订，不混版本。 |
| 修订频繁时，仍能展开分支、从具体节点找到历史，不得靠减少树大小通过验收。 | 用 **5 MB 及更大**的库持续追加小修订，同时读取子树、引用和历史分页；记录数据规模、扇出、预算、读写延迟及所用索引。检查局部查询不全表扫描，局部提交不重写全树。不预填吞吐或延迟承诺。 |
| 自举后能追到 T1.3.1 的原判断，#8 指回五个节点。 | 对照手稿核对 ID、引用、历史精度；再次导入不覆盖已存在的产品树。 |

本稿供人评接口与取舍。以上是实现阶段的验收场景，不是已有功能或压测结果。P3 浏览器原型按其实际实现走查；本稿不能作为原型已具备上述操作能力的证据。网页体验与真实 DSH 接入分别验收。
