# 过程材料与增量形式化

## 目标

人照常讨论，不填表、不逐条提交。Agent 在确认判断、要求记录、话题或阶段转换时，根据当前对话增量写树；写不成判断但值得保留的片段独立留档。树仍是正式阅读面。这个版本不做画布、过程 UI、历史会话扫描或后台代写，也不验证树比好文档更好。

## 路径

```text
当前对话 + 当前树 → skill 判断是否值得记录
  ├─ 可以独立说明的判断（包括可说明的未决）→ 现有树写入工具
  ├─ 还不能安全入树、但值得保留 → 另存文本，返回过程 ID
  └─ 没有值得记录的变化 → 不写

指定旧过程 ID → 点读文本作为参考 + 重读当前树
  ├─ 形成了新判断 → 新写一条
  └─ 已被吸收、不再成立或仍不清楚 → 不写
```

未留档和未入树可能都是正常结果；已经形成且该记却没记才是漏记。结束会话、草稿过久不触发补交。留档正文可以不完整，不要求当时记录「为什么没提交」、绑定节点或基线。旧材料可读，不可编辑或发布，不变基，不作为自动授权。已入树的判断照常用勘误、剪除等操作保留演变，不通过过程存档修补树历史。

## 工具与存储边界

- `cognition_tree_process({treeId, action: {kind:"save", text}})`：在已有树下保存一段非空白 UTF-8 文本，最多 16 KiB，返回 `{treeId,processId}`。相同树和相同正文重试得到相同 ID。不要求附带理由或其他结构字段。
- `cognition_tree_process({treeId, action: {kind:"read", processId}})`：显式点读，返回 `{treeId,processId,text}`。没有枚举接口。同一个已注册工作区内的会话可凭定位符读，不是会话私密存储；其他工作区读不到。没有确认、编辑、删除或发布操作。只读会话可点读但不能保存。
- 过程材料独立保存在工作区 `.converge/process/`，用完整记录的原子目录发布避免读取半写内容；普通树查询、历史、待确认与提交通知不读取这批材料。树 SQLite 格式不改，也没有草稿和树的双写：新写入不自动回填过程材料。
- 现有 `add_branch` 和 `decide_node` 可选 `expectedStamp`。它只用于新写入：从刚读到的 `stamp`（CTV2 的 `t`）获得，由事务核对；过期拒绝，需重新读与判断。不传时保留既有行为。勘误与复活仍是各自的现有操作，没有新增跨记录原子改判 API。

## 实现与验收

DSH 工具校验可信会话和文件权限，现有 worker 做档案 I/O；内核与存储负责树版本和正式写入。位于项目 `.dsh/skills/incremental-formalization/` 的 skill 描述触发时机、写法和续接。npm 包附带 skill 文本，需要启用的工作区自行添加；启动插件不监听或拦截对话。

工程验收覆盖同工作区跨会话点读、跨工作区及跨树隔离、只读拒存、树读面隔离、材料重复保存、损坏与文件路径边界、版本过期拒写。写侧使用效果需另行实测：用同一多轮讨论观察漏记、重复、误剪/误勘误和催写/纠正次数，检查读者仅靠树能否恢复现行结论与改判理由；自动化通过不等于该体验假设已验证。
