# 认知树 MVP · UX 设计稿（P3）

**性质：**P3 可点原型的设计稿。阅读交互与外观可参照本稿；当前网页的执行、确认和存储边界见[实现设计](<implementation.md>)。[主阅读方式 Q5](<../open-questions.md>) 由人看过原型后再定；第六节对[内核接口单](<kernel-interfaces.md>)的增补与解读也要经人评审，P4 才写进正式内核。原型在 [adapters/browser](<../../adapters/browser/>)，启动方式见[产品入口](<../../README.md>)。

**人的要求（转述）：**整体气质深沉、内敛、克制而不失风度，引人深思；避免元素堆砌和炫彩，突出核心能力，编辑体验要优雅。视觉干净，细节文字信息量不宜过大，必要时再展示；支持原地编辑，不用按钮切换；保留动效但不突兀、不炫技。以及[人的决定](<../PRINCIPLES.md>)中的要求：UX/UI 初版必须现代化、认真设计，并可单独测试。

**人已拍板：**

- 视觉采用“纸上的推导图”方向（第四节），人看过概念图后认可。
- 外观有四套：浅色“纸本”“青瓷”“暖砂”与深色“夜读”，缺省跟随系统深浅色；换外观在设置弹窗里，产品界面不放常显的切换按钮。
- 待处理的提议和时间线原地进入，不设页签。
- 原地编辑不改判断原文：状态、剪除理由、复活条件和勘误都在所属位置直接写；勘误仍是该判断下的子判断。

本稿其余内容是 AI 的提案，等人评审。

## 一、目标

人在一棵认知树里做三件事，每一步都看得出是谁确认的、为什么：

1. **追问**：从根问题沿推导链走到某个判断（包括被剪的方案），读到依据、剪除理由、复活条件和关联实例；去看别的分支后，一步就能回来。
2. **纠偏**：看清 AI 的新提议长在哪里、与什么相关；人在原处确认、剪去、接受替代或勘误。需要理由的决定当场写下，记下成功之前不显示成功。
3. **看清范围**：分清“参数没要求读”“预算先到、还能续读”“确实没有”；读得不全时不冒充整棵树。

体验上把树当作一页可以细读的推导图。界面退到内容后面：常显的只有树形、标题、状态和三个问题的答案摘要，细节点开才出现。节点位置稳定，可以平移和缩放；每次变化有一次轻而短的过渡，说明发生了什么。验收场景沿用[总架构](<../ARCHITECTURE.md>)第三节。

**不在本稿：**正式内核与 SQLite 存储（P4）、DSH 侧栏与提议卡（P5）、Q4 的正式自举、自动 UI 探针。

## 二、信息架构

```text
顶栏    认知树 │ 根问题                    待看 N · 查找 Ctrl K · 设置 · v版本
左栏    大纲（「空间 + 大纲」时出现；「大纲」方式下占满左栏与主区）
主区    空间：径向 / 横向树 / 纵向树（设置里换）
        左下状态行：全景 · N 个判断 · 阅读方式        右下：看全 F
右栏    阅读栏：一个判断的一页；引用、经过和整棵树的时间线都在这里原地展开
底部    开发坞（只在独立网页出现，默认收成一行）
设置    换外观与图布局的弹窗；点遮罩、「关闭」或 Esc 收起
浮层    只有三种：查找、设置、出处阅读器（浏览器宿主）
```

查找的列表只列状态符号、标题与状态对，不显示 ID；需要 ID 时用阅读栏的「复制 ID」。三栏并排，以 1px 细线分隔，不浮在空间之上。「待看 N」只在有未确认的 AI 提议时出现。不用轻提示：成功、失败和新到的提议都在发生的位置说明。

| 区域 | 回答什么 | 常显 | 按需出现 |
| --- | --- | --- | --- |
| 空间 | 整体是什么形状、我在哪、它连着什么 | 树形、状态符号、标题（超过 14 字省略）、视野边界的芽 | 悬停或选中时显示全文与状态；选中时显示引用弧。ID 不在空间里露出，用阅读栏的「复制 ID」取用 |
| 大纲 | 逐条读、用键盘走 | 状态符号与标题、边界行；AI 提出的行加小字「AI 提出」，只为连通补入的行加「连接」 | 悬停或选中的行显示引用数；悬停表头时显示「全部展开 · 收起」 |
| 阅读栏 | 为什么、排除过什么、还有什么没定、谁确认 | 状态对、标题、正文前三行、三问各一行 | 正文全文、依据全文与来源、被剪子判断的理由、引用、本判断的经过、整棵树的时间线 |
| 顶栏 | 在哪棵树、有什么在等我 | 根问题、查找、版本；有提议时显示「待看 N」 | — |
| 状态行 | 视野多大、用哪种阅读方式 | 全景或聚焦、判断数、阅读方式 | 视野参数句、读取失败说明 |
| 设置 | 换哪套外观、哪种图布局 | 当前选择 | 候选的名字、说明和色块；点一下立即生效，记在本机浏览器 |
| 开发坞 | （仅浏览器）制造 AI 输入、观察存储与预算 | 收起时只有一行 | 预设场景与自拟提议；版本、存储大小、最近一次读取的开销；模拟延迟、让下一次保存失败、清空测试存储；外观（跟随系统 · 纸本 · 夜读） |

三种阅读方式就是 Q5 的候选，读同一份视图投影，共用选中、悬停和续读，切换时不丢位置。切换用状态行里的文字或按 1/2/3。

**阅读栏的一页**从上到下是：

1. 有上一个选中时，顶部一行淡字「‹ 回到 T…」。判断不在当前视野里时，另有一行「不在当前视野 · 以它为焦点」。
2. 元信息行：「复制 ID」（点一下把判断的稳定 ID 写进剪贴板，原地显示「已复制」）· 分支状态（符号加字）· 确认程度（符号加字，人确认时加朱印）。ID 本身不在界面上显示。来历不是普通分支时，加小字「补充」「勘误」或「替代 T…」，被替代的 ID 可点。
3. 标题和正文。正文最多三行，超出部分以省略号截断，点正文本身就展开。正文下一行极淡的「写一句勘误…」。
4. 三问分节。每节只有一个小标题和一到几行，没有内容的节不出现：
   - **为什么剪去**：只在这个判断本身被剪时出现，排在第一，始终展开。写出剪除理由和「重新考虑的条件」；缺项时标「缺项 · 未记录复活条件」，不替它编造。因接受替代而被剪时，再写一行「由 T… 替代」，ID 可点。
   - **为什么**：一行摘要，依次取依据、来源、确认说明中第一个有内容的，带出处链接。行尾有 ›，点开显示三者全文。三者都没有时，这一节不出现。
   - **排除了什么**：被剪的子判断，每条一行标题；理由默认收起，点那一行展开。
   - **留下的**：留下的子判断，每条一行标题。
   - **还没定**：未决原因；未决的子判断；所有 AI 提出、待确认的子判断（不论分支状态，只列在这一节）；指向这个判断的替代提议。没有时写明是“范围内已读完、没有未决”，还是“这一支还没读完 · 续读”。
   - **状态未载**：手稿没有记录分支状态的子判断，单列在最后，不归入以上几类。
5. 页尾两行淡色的入口：「引用 · 出 N · 入 N ›」（没有引用时不出现）和「这条判断的经过 · N 条 ›」，点开后在原处展开。

列表里只标例外：AI 提出、待确认的子判断用铅灰虚线符号；人确认是常态，列表里不盖朱印。没有选中时，阅读栏显示根问题这一页，页尾一行淡字列出快捷键。

**时间线**（整棵树的，或一条判断的经过）按日分组、从新到旧。每条写动作、理由和行为者；「形成」和「人确认」分开标注，「人确认」条目带朱印，导入的手稿记录标「导入」。

**快捷键：**Ctrl K 或 / 查找；F 看全；B 回到上一个；1/2/3 切换阅读方式；Ctrl ↵ 记下；Esc 由近及远：关闭浮层、收回书写区、收起展开项或时间线，最后取消选中。大纲里用方向键移动、展开、收起；在空间里双击判断推近。

## 三、主流程

```text
进入 ─ 树不存在 ─▶ 一句说明 +「导入样例 T1」─▶ bootstrapTree ─▶ 读回 ─▶ 开场
     └ 树已存在 ─▶ 全景读取 ─▶ 开场：树枝由根向外按层画出，标签随后淡入（一次，不超过 0.8 秒）

追问：选中判断（空间 / 大纲 / 查找 / 待看 / 时间线条目）─▶ 推导链加深、其余退淡；目标在可视区外时镜头平移
      ─▶ readNode + 补读一层邻居 ─▶ 阅读栏淡入这一页
      ─▶ 点一行，原地展开细节（剪除理由、依据全文、引用、经过）
      ─▶ 点出处 ─▶ 出处阅读器打开原文，标出引用指出的局部
      ─▶ 去别处后，「‹ 回到 T…」或 B 一步回来

视野：点状态行的「全景」或「聚焦 T…」─▶ 状态行上方原地展开参数句，焦点缺省为当前选中的判断：
      以 T… 为焦点，向下 2 层，沿引用 1 跳（出向，从落点起跳，跳后 1 层），预算 扫描 · 节点 · 字节，超出时折叠
      （带下划线的值点一下就能选，选中即重新读取；Esc 还原到展开之前的视野；句末「回到全景」）
      ─▶ 「+」芽：参数范围到此 ─ 点击 ─▶ 从该处续读一层
      ─▶ 「⋯」芽：预算先到 ─ 点击 ─▶ 续读
      ─▶ 报错模式超限 ─▶ 状态行上方一行说明，视野保持上一次成功的结果，可「改为折叠」

AI 提议：开发坞场景或自拟 ─▶ AI 入口 proposeBranch ─▶ 内核存为「AI 提出 · 未确认」并记形成
      ─▶ 提交通知 ─▶ UI 读回 ─▶ 新判断在父判断旁淡入，顶栏「待看 N」
      ─▶ 点「待看」选中最新一条；正看着一条提议时显示「待看 2/3」，再点依次到下一条

时间线：点顶栏版本号 ─▶ 阅读栏原地显示整棵树的时间线 ─▶ 悬停一条，空间里标出相关判断
      ─▶ 点一条就选中那个判断；再点版本号或按 Esc 回到原来的判断

人决定（都在阅读栏原地发生）：
      点状态词 ─▶ 行内列出允许的去向 ─▶ 选「剪」或「留 / 未决」─▶ 标题下长出书写区
      点「待你确认」或「由你确认」─▶ 直接记下，不用填写
      点「比较后接受…」─▶ 引出被替代判断的原文 + 书写区
      点「写一句勘误…」─▶ 正文下长出书写区
      ─▶ Ctrl ↵ ─▶ decideNode ─ 成功 ─▶ 提交通知 ─▶ 读回 ─▶ 过渡，版本号加一，书写区变成正文
                              └ 失败 ─▶ 原地显示「没有记下」和原因（存储失败已回滚，树不变）；书写内容保留
      Esc ─▶ 收回书写区；已写的内容留作草稿，这次打开页面期间再次打开同一决定时恢复
```

| 人的决定 | 什么时候可用 | 从哪里发起 | 人要写什么 | 结果与过渡 |
| --- | --- | --- | --- | --- |
| 确认 | AI 提出或确认未载，且不是替代提议 | 确认程度旁的「待你确认」（AI 提出）或「由你确认」（确认未载） | 无 | 只改确认程度，不新增节点；时间线记一条「人确认」；轮廓由虚线收成实线，朱印淡入 |
| 剪除 | 不是根，也还没剪 | 状态词 → 剪 | 为什么不走这条路？什么变化会让它值得重新考虑？（都必填） | 节点保留；树枝变成虚线并出现断口，标签退淡；记形成 |
| 重新启用 | 已剪 | 状态词 → 留 或 未决 | 条件发生了什么变化？（必填）；书写区上方引出旧理由与复活条件 | 旧理由与复活条件写进这次修订；树枝恢复实线 |
| 定为留 / 重新打开 | 当前为未决 / 留的非根判断，待接受的替代提议除外 | 状态词 → 留 / 未决 | 为什么现在可以留下 / 需要重新考虑？（必填） | 只换分支状态，不增节点、不改确认程度；转换和理由记入形成记录 |
| 接受替代 | 未剪的替代提议 | 确认程度旁的「比较后接受…」 | 为什么剪去旧判断？什么变化会让旧判断值得重新考虑？ | 一次提交：确认新判断、剪除旧判断、记下旧新 ID；两处过渡同时发生 |
| 人勘误 | 任何判断 | 正文下的「写一句勘误…」 | 勘误后的判断（必填）、哪里不对（可选）、留或未决（行内选，缺省为留） | 新增一个已确认的勘误子判断，原话不改；新子判断从父判断长出 |

**状态词只列内核允许的去向。**「留 ↔ 未决」走[接口单 §3.1](<kernel-interfaces.md#31-判断状态与写入>)的 `setOpenOrKeep`；已剪的判断回到留或未决仍是重新启用，状态未载只能去剪，根没有去向。重新打开的理由在该判断的经过中可查，正文里的未决说明保留为原始资料。

**书写区：**左侧一条 1px 竖线，表示“正在写，尚未记下”。输入框没有边框，只有一条极淡的底线，用衬线正文字号；空着时把问题当提示语，开始书写后，问题缩成框上方的一行小字，始终看得见。下面一行最淡的键位提示，例如“Ctrl ↵ 记下 · Esc 收回 · 两项写完才会剪去”。不放保存或取消按钮。必填项没写完就按 Ctrl ↵ 时不提交，提示里对应的字短暂变成赭石色。

**记下之前不预演结果：**书写时，元信息写成「未决 → 剪（未记下）」，目标状态用铅灰色；空间里的节点和树枝都不变。按 Ctrl ↵ 后，竖线旁显示“记下中…”，输入框变为只读；读回成功后才播放过渡。

替代提议不能用一键确认，只能比较后接受，或者剪去。以 AI 身份确认（越权）和依赖前提指向祖先（不合规草稿）都由内核拒绝，开发坞把这两种情况记为“按预期被拒绝”。

## 四、视觉方向：纸上的推导图

隐喻是一页摊开的手绘图谱：根问题在中央，判断按层向外生长；树枝是细线，选中时推导链被墨色描深；被剪的路留在纸上，只是变淡、断开。AI 的提议像铅笔写下的虚线，人确认时盖一方朱印。

1. **内容先于界面。**只用细线、留白和字的层次组织页面。不用发光、模糊、渐变、投影、星空与粒子；圆角不超过 3px；控件就是文字，不用胶囊按钮、图标按钮组和分段切换。
2. **颜色少而准。**底和字是暖中性色。语义色只给少数领域值，都是低饱和的矿物色。全界面唯一的饱和色是朱印，只在阅读栏的状态行和时间线的「人确认」处出现。
3. **形状和线型是主编码，颜色只做强化**，灰度或色弱时仍读得出状态。
4. **两种状态始终成对、分开显示**：分支状态与确认程度在空间、大纲、阅读栏和查找里都各自显示。“剪 · 人确认”不会被读成“判断是错的”，“留 · AI 提出”也不会被读成“人已同意”。
5. **焦点靠明暗，不靠颜色。**选中时，推导链和直接子枝用墨色加深，其余树枝退淡。
6. **细节按需，但要找得到。**常显内容只回答三件事：是什么、什么状态、三问的结论。来源、引用和经过在悬停、选中或点开时出现；ID 不显示，由阅读栏的「复制 ID」交给 AI。能点开的行，行尾有一个淡淡的 ›；能编辑的文字，悬停时出现点状下划线。
7. **原地编辑。**所有决定都在所属文字旁边发生。没有查看与编辑两种模式，没有保存或取消按钮，也没有弹窗表单。
8. **过渡解释变化。**只用透明度、线型和位置的过渡：交互 120–420ms，首次进入不超过 0.8 秒。不弹跳、不缩放、不循环。系统打开“减少动态效果”时取消全部过渡，静态外观仍然完整。
9. **保住位置记忆。**布局按 UI 已读到的全部节点计算，抖动由节点 ID 的哈希决定，刷新后不变。全景读过整棵树以后，切换聚焦或改选判断只移动镜头，不挪动节点；读入新节点时布局平滑调整。换图布局时节点按过渡移到新位置，同一种布局内位置不再变化。

**图布局。**三种布局都只由已读节点决定，都可以随时换、立即生效，记在本机浏览器：

- **径向**：根在中央，判断按层向外生长，分支按叶子数分角度。
- **横向树**：根在左，每层一列向右推进，兄弟按稳定 ID 上下排开，像目录树。
- **纵向树**：根在上，每层一行向下推进，像组织图。

标签跟着布局方向放到节点外侧（横向放右、纵向放下）；引用弧、边界芽和取景沿用同一套坐标。

**外观。**四套外观结构相同，只换令牌。纸本用燕麦色的底、象牙白的阅读栏和深褐墨色的字；夜读用乌木墨色的底、略亮一层的阅读栏和暖象牙色的字；青瓷用冷灰绿的底和松墨字；暖砂用暖驼的底和褐墨字。“淡淡的暖色”指燕麦、亚麻、米色一类；卡其本身偏深、偏黄绿，只适合作线和次要色。语义色（留 / 未决 / 剪 / 朱印 / 三种引用）四套一致，只换底、页、墨与线。缺省跟随系统深浅色，宿主可以指定（见 6.1），设置页可以换（见 6.3）。

**字。**判断用衬线（思源宋体），包括标题、正文、空间里的标签和书写区；界面控件和小标签用无衬线；稳定 ID 用等宽、小号、淡色。字号不按屏幕型号写死，随窗口宽度在最小与最大之间连续变化，窗口越宽字越大：判断标题 28–34px 加粗；正文 16–20px，行高 1.85；根问题在顶栏 18–22px、在空间是标签的 1.4 倍；空间标签 14–17px；界面文字 13–16.5px；ID 12–15px；最小的标记（补 / 勘 / 替、计数、键位）11–14px。1440px 宽的窗口取接近最小的一档。正文与说明文字对底与页的对比度在纸本和夜读里都不低于 4.5:1，占位文字不低于 3:1。

| 领域值 | 空间里 | 阅读栏（大纲只画同一组符号） |
| --- | --- | --- |
| 留 | 实心墨点 | 墨点 +「留」 |
| 未决 | 赭石色缺口细环，像一笔没画圆的圆相，缺口约 60° | 缺口环 +「未决」 |
| 剪 | 淡色空心圆加一道斜线；通向它的树枝变成淡虚线，近端留一个小断口；标签退淡 | 同一符号 +「剪」。不加删除线：剪不是删除 |
| 状态未载 | 很淡的空心小菱形 | 菱形 +「状态未载」 |
| 人确认 | 节点外轮廓为实线 | 「人确认」+ 朱印（只在阅读栏状态行和时间线） |
| AI 提出 | 节点外轮廓为铅灰虚线，标签也是铅灰色 | 虚线符号 +「AI 提出」；列表里只标这一种例外 |
| 确认未载 | 没有外轮廓 | 「确认未载」 |
| 补充 / 勘误 / 替代 | 标签前加小字「补 / 勘 / 替」 | 来历小字 |
| 依赖前提 / 同类实例 / 与事实冲突 | 只在选中或悬停时出现，分别画成细实线 / 点线 / 土红虚线；箭头保留原方向，弧中点用小字写类型 | 引用行：线型样本 + 类型 |
| 外部材料 | 不画：出处只在阅读栏打开，避免和标签、树枝抢位置 | 依据里的出处链接 |
| 视野边界 | 「+」芽：参数范围到此；赭石色「⋯」芽：预算先到；没有芽：范围内已读完 | 大纲里的边界行；状态行汇总 |
| 只为连通而补入的祖先 | 半透明 | 大纲里标「连接」 |
| 选中 | 节点外加一圈细墨环；推导链和直接子枝加深，其余退淡；标签加深 | 大纲行左侧一条 2px 墨线，底色略深 |

根问题的标签紧贴根节点，字号最大。标签放在节点的径向外侧：右半圈左对齐，左半圈右对齐，最多两行，超过 14 字截断，悬停时显示全文。标签之间、标签与树枝之间都不交叠；缩得很小、实在放不下时，优先保留选中、推导链和浅层的标签，其余暂时隐藏，悬停仍能看到。

| 时机 | 过渡 |
| --- | --- |
| 首次进入 | 树枝由根向外按层画出，标签随后淡入；只播一次，不超过 0.8 秒 |
| 选中或跳转 | 推导链加深、其余退淡，240ms；阅读栏内容淡出 160ms 再淡入 200ms，不滑动、不缩放；目标在可视区外时镜头平移，不先拉远再推近 |
| 悬停 | 标签加深，120ms |
| 展开或收起一行 | 高度与透明度，220ms |
| 状态词的去向、书写区 | 去向淡入 120ms；书写区展开 240ms |
| 记下中 | 竖线旁一行淡字“记下中…”，不转圈 |
| AI 提议到达 | 树枝从父判断画出 300ms，新判断淡入 400ms；「待看 N」的数字交叉淡入 |
| 人确认 | 虚线轮廓收成实线 300ms，朱印淡入 300ms |
| 剪除 | 树枝由实线淡成虚线并出现断口，标签退淡，400ms |
| 重新启用 | 剪除的反向过程，400ms |
| 接受替代 | 新判断的确认与旧判断的剪除同时发生 |
| 人勘误 | 勘误子判断从父判断长出：树枝画出 300ms，节点淡入 |
| 布局变化 | 节点从原处移到新位置，420ms |
| 没有记下 | 书写区下方淡入一行土红文字；不摇晃、不闪烁 |

## 五、设计令牌

令牌值只在 [tokens.css](<../../ui/src/styles/tokens.css>) 维护；组件样式只引用变量，不写裸色值，SVG 的描边和填充也用变量。四套外观用同一组变量名：缺省跟随 `prefers-color-scheme`；UI 根或其祖先元素上的 `data-ct-theme="paper" | "ink" | "celadon" | "sand"` 优先于系统设置。

| 类别 | 变量 | 规则 |
| --- | --- | --- |
| 底与页 | `--ct-ground` `--ct-page` `--ct-sel` | 空间与左栏用底；阅读栏、浮层用页；选中行用 sel |

| 线 | `--ct-line` `--ct-line-strong` `--ct-edge` `--ct-edge-faint` `--ct-edge-focus` | 分隔线、浮层边线、树枝、退淡的树枝、推导链与选中 |
| 分支状态 | `--ct-keep` `--ct-open` `--ct-prune` `--ct-unknown` | 只表示留 / 未决 / 剪 / 未载 |
| 确认程度 | `--ct-ai` `--ct-seal` | 铅灰只表示 AI 提出；朱砂只用于朱印 |
| 引用类型 | `--ct-premise` `--ct-example` `--ct-conflict` | 只表示三种引用 |
| 交互与反馈 | `--ct-link` `--ct-warn` `--ct-danger` | 交互色只用于链接、焦点环和当前项下划线；提醒用赭石色文字，失败用土红色文字，都不用色块 |
| 字体 | `--ct-serif` `--ct-sans` `--ct-mono` | 判断用衬线，控件用无衬线，ID 用等宽 |
| 字号与行高 | `--ct-fs-micro` 11–14 · `--ct-fs-id` 12–15 · `--ct-fs-ui` 13–16.5 · `--ct-fs-row` 14–17.5 · `--ct-fs-body` 16–20 · `--ct-fs-lead` 18–22 · `--ct-fs-label` 14–17 · `--ct-fs-root` 标签 ×1.4 · `--ct-fs-title` 28–34；`--ct-lh-body` 1.85 · `--ct-lh-ui` 1.5 | 每个字号是 `clamp(最小, 随 vw 增长, 最大)`，单位 px；1440px 窗口取接近最小的一档；组件只引用令牌，不写裸 px |
| 间距 | `--ct-s1..s10`（4px 基准） | |
| 圆角与线宽 | `--ct-r` 2px · `--ct-r-max` 3px；`--ct-hair` 1px · `--ct-edge-w` 1px · `--ct-focus-w` 1.25px | 圆角不超过 3px |
| 动效 | `--ct-ease-out` `--ct-ease-in-out`；`--ct-dur-hover` 120 · `--ct-dur-out` 160 · `--ct-dur-in` 200 · `--ct-dur-open` 220 · `--ct-dur-focus` 240 · `--ct-dur-mark` 300 · `--ct-dur-state` 400 · `--ct-dur-layout` 420 · `--ct-dur-enter` 800 | 单位 ms；“减少动态效果”时全部为 0 |

### 6.2 对内核接口单的增补与解读（待人评审，P4 之前定）

P3 原型替身内核（工作副本在仓库根 `.local-work/retired/`，不属于产品包）覆盖接口单 3.1–3.2 的基本读写。「留 ↔ 未决」是接口设计中的能力，不在此可点原型的实现和走查范围内。下表列原型为了呈现界面而增补或解读的契约：

| # | 项 | 原型做法 | 理由与代价 |
| --- | --- | --- | --- |
| 1 | 提交通知 `watch → TreeChange {treeId, stamp, revisions}` | 每次写事务提交成功后发一次，附本次新增的修订 | AI 的提议从别的入口（DSH 工具）进来，UI 需要知道树变了；过渡也按修订明细播放。代价是每个宿主都要有一条推送通道 |
| 2 | `Revision.detail` | 结构化记录动作、理由、复活条件、恢复后的状态、旧新 ID，以及被覆盖的旧剪除理由 `previous` | 时间线和过渡不用去解析叙述，旧理由仍能查回。接口单里只有 `summary` |
| 3 | `Revision.seq`，`by.kind = import` | 用树内单调递增的序号排序和分页；自举进来的手稿记录，行为者标为“导入” | 接口单提议按 `(at, id)` 排序，但按日精度的导入记录在同一天里排不出先后 |
| 4 | 边界标记 | 只标 `scope`（向前探一条，确认那边还有）和 `budget`；命中节点没有标记就表示已查尽；连接节点的其余孩子一律算未读 | 接口单列的是 `scope / exhausted`；不为每个已查尽的位置造标记，省字节 |
| 5 | `TreeView.cost` | 返回实际的扫描次数、节点数、字节数 | 供开发坞观察预算 |
| 6 | 续读 | 不用游标，从边界节点发起一次新的 readView，UI 按 ID 合并 | 原型没有实现 `cursor / viewExpired`；正式内核仍按接口单 |
| 7 | 待处理提议 | 「待看 N」的计数和跳转取缓存里所有 `aiProposed` 节点，依赖全景已读过整棵树 | 5 MB 的树不能靠全景；正式内核需要一种按确认程度读取待处理提议的方式 |
| 8 | 新 ID | 父 ID 加“.”和递增序号；引用为 `ref-<from>-<n>`，修订为 `rev-<seq>` | 可读、稳定、不复用 |
| 9 | AI 提出剪除 | proposeBranch 的草稿可以是剪（须带理由和复活条件），显示为“剪 · AI 提出”；人可以确认剪除，也可以重新启用 | 接口单的 Draft 已经允许，原型补上了展示 |
