# 人已决定什么

这里记录项目所有者确认的约束，不把 AI 解释写成原话。表里的“落点 / 边界”是这些决定对 MVP 的含义，不是已经实现的功能。尚未决定的事项单列在[待决问题](<open-questions.md>)。

## 产品与工程

| 人的依据（转述） | 决定、理由与边界 |
| --- | --- |
| 内核的运行不直接依赖宿主；初版提供 DSH 适配层，可直接进入 DSH 使用。 | 树规则独立运行，DSH 是首发真实入口，而不是内核的一项前置服务。不能仅交付网页演示当作已接入 DSH。 |
| 假设未来还有其他适配层，且有 MCP。 | 不用 DSH 工具的参数格式定义领域模型。保留并列接 MCP 的位置；首版不实现 MCP 服务。 |
| UX/UI 初版必须现代化、认真设计，并可单独测试；UI 内核加不同环境适配。 | 两个环境使用同一套 UI。独立网页用于设计与验证，DSH 嵌入不能是另一份页面。真实宿主集成单独验收。 |
| 文件夹结构即架构；按代码职责分层而非功能职责分层，功能划分落在模块。 | 要从目录看出谁持有状态、谁解释规则、谁接环境。需总架构、前后端、文件结构四个视角，见[架构](<ARCHITECTURE.md>)和[结构](<STRUCTURE.md>)；不是给每个功能再造一套后端和 UI。 |
| 较重的流程（例如必须 AI 审计）可以放宽，设计阶段尤其如此。 | 人决定设计并验收，AI 提交可否定的方案和可复核的证据；不强制独立 AI 审。用 ProjectBoard 是为了跨会话看见开发事实，不是把人审交给看板。具体协作方式：设计由人决定并验收，AI 在授权范围内执行并把证据交回人。 |

## 选项和默认项的确认

- 人选定的组合（1A、2A、3A）：产品在 **Converge 根仓的 cognition-tree/**，研究材料不迁移；层名采用 types / utils / operations / commands / models / modules 那套语汇，内核含 queries、catalog，UI 有 hooks、components；正式认知数据在**所属工作区的 .converge/**，不在 DSH 用户目录。单树存储边界见 Q3；具体引擎与字段由人评接口单。
- 人先表示除不引入测试框架外不反对，随后同意按 AI 的最新推荐实施：采用 **Vitest**；共用 React 18（DSH 用宿主实例，独立网页自带）；UI 手动验收、默认不跑浏览器探针。绘图用的浏览器不是 UI 探针。测试框架是开发依赖，不是内核运行依赖。
- 同一次同意按 AI 最新推荐实施时，也采纳了**用任务板**：项目、五阶段计划和证据归板，设计依据归仓库，不设第二份进度账。人的完整授权还包括做完后停手，确保下一步跨会话可恢复；阶段交付供人验收，开工授权不自动延续到下一阶段。Git 提交由人决定。

## 认知树本身

骨架是“节点是判断，不是发言”（T1.2）以及“树 + 有类型引用边”（T1.3.3）。何处长出分支、何处被剪，都诚实保留。确认来源、理由和反例可沿[手工自举树](<../../认知树.md>)按稳定 ID 回查。

人确认了列出的五项，对应的集合如下。此处不是批准任何尚未列入这五项的子方案。

| 节点 | 确认的设计 | 它防止什么 |
| --- | --- | --- |
| T1.2.2 | 剪枝记录理由与复活条件 | 条件改变后，无法知道为什么应当重新考虑 |
| T1.2.3 | 形成过程只记改变树形状的事件 | 把讨论流水账误当认知 |
| T1.2.5 | 维护认知树与确认判断是两件事，见[操作边界决策树](#人与-ai-操作边界决策树) | 把 AI 的输出误记成人机共识 |
| T1.3.3.1 | 引用边类型少而固定；新增要说清在回答什么新问题 | 把树退化成任意连线的通用图 |
| T1.3.3.2 | 存储与展示分离 | 为了渲染“另见”而复制或改写树的推导关系 |

T1.2.4（概念单独成层）仍未决，未纳入 MVP。把一种结构用于 MVP 是产品选择，不是它已改善认知对齐的实验证明。

## 接口单的产品前提

| 已拍板的问题 | 对产品的要求 |
| --- | --- |
| Q1 · 正文与替代 | 不开放直接覆盖已保存正文的入口。补充、勘误保存在原节点下；替代判断是旧判断的同级新分支。执行替代时剪旧枝并记录新旧 ID、理由和复活条件；旧原文和引用仍能查回。 |
| Q2 · 状态与时间线 | 单纯确认、剪枝、重新启用都不另造节点。修订日志关联实际发生时间和稳定节点 ID；单纯确认在时间线上标为「人确认」，树形变化和分支取舍另标形成事件。 |
| Q3 · 分文件 | 每棵树一个正式存储单元，节点、引用和修订日志保存在一起，不另养业务日志文件。 |
| 工作区建树（“面板和 AI 工具都能建”“把导入手稿关掉”） | 人或 AI 从一个根问题创建独立树，创建行为留痕但不算人确认。DSH 工作区不提供手稿导入入口，不预填其他项目的判断，不覆盖已有树。 |
| 归档（“只有UI能操作归档和恢复”；选择 A） | 可从 DSH 界面归档整树或一个节点及其子树；默认查询不返回归档对象或任一端归档的关联。恢复保留原位置与引用，独立的子归档仍有效。归档是可见性管理，不是剪枝、删除或人确认。 |
| Q4 · Converge 的 T1 | 已从[手工树](<../../认知树.md>)自举的 T1 保留原 ID、引用、确认来源和历史；导入不是重新确认。之后以产品树为准，保留手稿，不双向同步。 |
| Q6 · 留与未决 | 判断本身没变时，可以在「未决」和「留」之间原地转换；手稿没有记下分支状态的判断，也可以这样直接定为留或未决。保留节点 ID 与正文；说明理由，按形成事件记入时间线，不把这项决定记成单纯确认。 |

**读写的日常负载。** 单树 5 MB、高频修订、历史继续增长，是读写设计的起点，不以 MVP 为由缩减。一次修改与相应日志同一事务提交；成功后能重开，失败不报告成功。不为此建设权限框架、跨进程写入协调或灾难恢复系统。DSH 后端采用工作区 `.converge/` 下每树一个 SQLite 主库。人的授权范围是按方案实施、先不动正在使用的 DSH：先实现并在隔离工作区验证保存、重开和回滚；不改真实 profile、不重启，也不自动迁移浏览器数据。见[DSH 接入设计](<design/dsh-adapter.md>)。

## 人与 AI 操作边界决策树

**变更可以先于确认生效；只有人能确认。** 这是产品决定，不表示[接口单](<design/kernel-interfaces.md>)或原型已经支持。

```text
要对认知树做什么？
├─ 只读局部树、节点正文或历史 → 人和 AI 都能做，不写日志
└─ 写入
   ├─ 会覆盖已保存正文，或不能保留可回查的历史 → 不开放入口
   └─ 能保留原文与历史
      ├─ 记为「人确认」 → 仅人能明确确认，AI 不可代做
      ├─ 创建工作区树 → 人和 AI 均可；只建未确认的根，不导入手稿
      ├─ 日常变更 → 人和 AI 都能执行，保存即生效，不用等人审批
      │  ├─ 新增普通分支、补充或勘误 → 保存新节点，保留原文
      │  ├─ 剪除、重新启用、留 ↔ 未决（含为未载的状态定下留或未决）→ 原地改变状态并留痕
      │  └─ 执行替代 → 保存新旧关联并剪旧枝，不等于人已确认替代
      └─ 其他写入 → 不因这条规则开放新入口
```

- 人和 AI 的写入都要能查到执行者、时间、稳定节点 ID 和发生的变化；变更和修订记录一起提交。剪枝和替代保留剪除理由与复活条件。
- 新变更不论由人还是 AI 执行，都标为未经人确认；人可以按需确认，不必逐条点过。人自己执行的变更也一样，需要时另行确认，执行与确认不合并成一步。例如，AI 剪去一个人已确认的判断：它保存后就是「剪」，这次剪除未经人确认；原判断和早先的人确认仍可查回。

## 从整棵树折出一个视图

- 调用方指定普通子树的深度、引用跳数、出向／入向／双向、每轮从落点还是从其展开子树起跳，以及跳后展开多深。沿引用读到一个节点，不改写它在原树上的父节点。
- 节点按稳定 ID 去重，保留命中引用的类型和原始方向；只补齐连接所需的原树父链，不因补入祖先额外展开分支。
- “完整”指每次成功返回的部分本身是一棵可读的树，不等于一次展开无限扇出。读取时限制实际扫描量、节点数和返回字节，父链也计入；区分参数范围以外、预算未读完和确实没有关联。可续读；要求一次取全且超限，就明确报范围过大。
