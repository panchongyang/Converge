# 认知树术语

用一个节点区分两件事：**“剪 · 人确认”**表示人确认了当前的取舍，并不表示判断本身正确；**“留 · AI 执行 · 未确认”**也不表示人已同意它。

| 词 | 在这里指什么 |
| --- | --- |
| 根问题 / 判断节点 | 根给出所问的问题；分支记录对问题做出的判断，不以一次发言作为节点。稳定 ID 用于指认节点，不因剪枝而复用。 |
| 树边 / 推导链 | 子节点从唯一父节点长出。沿父链回到根可以回答“为什么走到这一步”；引用不算第二个父节点。 |
| 分支状态 | 留、剪、未决；描述如何对待这个判断。剪是保留排除项、理由及复活条件，不是删除。 |
| 确认程度 | 人确认、未经人确认，或导入手稿未载。它描述当前变更或导入判断的确认程度，独立于分支状态和执行者。人自己执行的变更也不自动确认。 |
| 依赖前提 | 指向祖先链以外的前提。前提变了，能查到哪些判断要复查。 |
| 同类实例 | 指出另一处同一原则或失效模式的例子；不改变推导链。 |
| 与事实冲突 | 标记某个判断与外部可指认事实不一致；标记不裁决冲突，不改任一方。 |
| 修订日志 / 时间线 | 日志保存认知变更，时间线按发生时间和稳定节点 ID 展示。只有确认程度变化也有一条「人确认」；阅读、展开和看板操作不在其中。 |
| 形成记录 | 时间线中说明树如何长出、剪除、反转、重新启用，或一个判断为何在留与未决之间转换的记录。单纯确认可见，但不冒充形成事件；两者的边界见[人的决定](<PRINCIPLES.md>)。 |
| 存储 / 树视图 | 存储保留节点、真实父子关系和有类型的引用。树视图从中取出一部分：节点只出现一次，引用不是第二个父节点，补入父链只为连通。视图折叠不是剪枝，「没读完」也不是「没有」。 |
| 内核 / UI 内核 | 前者拥有树规则及用例；后者拥有可复用视图、交互及视图状态。UI 内核不是第二个能够提交领域状态的内核。 |
| 端口 / 适配层 | 端口声明内核或 UI 所需的能力；适配层把文件、浏览器、DSH 等具体环境接上去。运行时调用端口，不等于源码依赖其具体实现。 |
| catalog / actor | catalog 是共用操作目录；actor 表示调用方的业务身份（AI 或人），由入口识别而非调用方自报；“按协议允许”不等于“人已确认”。 |
| 人确认 / 人验收 | 前者针对**树上的判断**，后者针对**看板上的工程任务**；两者不能互相触发。 |
