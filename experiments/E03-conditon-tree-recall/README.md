# E03 恢复契约重现：认知树与项目文件

实验记录：两种模型配置各完成四种材料条件，共八个认知重现样本。不是 AgentWorkflow 的实现验收，也不是对树中判断的人类确认。

## 目的

用「一次运行中断后，凭什么知道下一步该做什么？」检验不同材料条件下的复述：只读认知树、只读项目内已有文档和源码，或同时可读两者。只读文件的条件再比较自由检索和额外指定一份必读档案。要求说出各项设计的「为什么／为什么不」。分别看**是否复述准确**、**重现了多少目标契约**，以及能否区分现有实现、目标契约和未决项。

### DeepSeek flash1017：五处认知偏移

被试正确复述了恢复的主线：以已提交事实为准，节点承担已接受输入的恢复责任，不盲重做副作用，未知不等于失败。它也找到了混合 Run 的目标验收例子，说明并发结清不能只靠 `handled` 水位，并指出待投递集合等价不代表恢复前后的全局序列等价。

主要失分在于：回答后半段虽然知道若干旧判断已被勘误，前半段仍把这些旧判断用现在时写进了同一套设计。

### GPT‑6.2 Sol：未发现需要扣分的偏移

## 样本能说明什么

- 指定必读相对各自的自由检索轮，Sol 覆盖从 36 到 100（+64），Flash 从 51 到 81（+30）。两者的总用量也都下降。准确性则不同：Sol 保持 100，Flash 从 89 到 88。**找到更多目标要点，不等于复述更准确。**
- 树组覆盖分别为 Sol 100、Flash 93。指定必读让本次 Sol 追平树组，Flash 仍低于自己的树组覆盖。这说明本次阅读指定档案不保证完整重现，也不能仅凭答卷断定自由检索的 Sol 没读到档案。
- 两种配置的混合只读轮都是各自用量最高的单次样本：Flash 为 1,604,964 tok、覆盖 69，Sol 为 324,926 tok、覆盖 91。两者的覆盖都低于各自的纯树轮和指定必读轮。不能据此断定混合材料导致覆盖下降，也不能把混合轮用量归因于逐节点读取。
- 最值得复测的是行为分支：宿主查不清时还会不会重发或结清；一个节点已经结清后再掉线，另一个节点是否会被错误跳过。
- 每个模型配置与材料条件的组合各一次，不能断言覆盖、准确性和用量差异可稳定复现。两模型的推理强度标签也不相同，不能把差异单独归因给模型。第一轮 Flash 关于实现缺少类型／测试约束的说法未核验，不作为证据或扣分项。

「认知树＋项目文件」轮运行中的截图显示：浏览 `AW03-Recovery` 的结构后，为取得多个节点的完整正文，模型逐个 ID 请求 `cognition_tree_read_node`。截图可见至少 8 次不同节点的单独读取。**问题是多节点正文分散成多次工具调用**，不是截图证明了同一个节点被重复读取。这样会增加调用次数，可能增加模型往返和 Token 用量；具体增加了多少尚未测量，不能把整轮消耗都归给这个缺陷。该截图只证明运行中的局部读取行为；同一轮的最终用量见第七轮，不用中途用量代替。
