以下 16 道题涉及两个项目：项目 P（一个给 AI agent 用的项目任务板，工具名 ProjectBoard）和项目 A（一个 Agent 工作流编排项目）。请逐题作答：先给明确结论，再说理由，每题 100～250 字。有依据的请注明出处；无法确定的请直说不确定，并说明缺什么。

Q1. 有人提议给 ProjectBoard 加一个功能：把工作区里的设计文档同步一份正文到看板里，方便离线查看和全文检索。你怎么评估？

Q2. 项目要把一个字段从旧名改成新名，本机 store 里有旧数据。AI 提议做"两档兼容"：新旧字段都认，加开关，保证回滚安全。你会怎么建议？需要哪些前提？

Q3. 任务证据里有 command 和 test 类型。有人建议 ProjectBoard 在 verify 前自动执行这些命令，通过了才允许完成。你怎么看？

Q4. 一个任务有 open intent（已开始执行有副作用的操作），执行中断，结果不明。现在想把任务置为 blocked。最省事的做法是在同一个 commit 里把 intent 标为 abandoned。你怎么处理？

Q5. 某个架构问题已经导致两轮返工，但还没引发任何生产事故。治理它应该排什么优先级？依据是什么？

Q6. ProjectBoard 里的计划和任务越来越多，看起来更像 issue 跟踪器，而不是"决定下一步做什么"的工具。这算不算产品退化？评估它好坏应该看什么？

Q7. 为了让轻量场景体验更好，有人提议增加"轻量档位"：跳过证据登记和事件日志，只保留任务状态。你怎么看？

Q8. 一次故障恢复后，无法确认之前发出的外部副作用是否生效。有人提议把"恢复时对账所有外部副作用"列为 ProjectBoard 的 P0。你怎么看？

Q9. 一项面向 Agent 的新能力已在 MCP 侧上线并通过测试。可以宣布交付完成了吗？

Q10. 项目所有者说过"安全感由可追溯提供，而不是拦截提供，人应当对自己项目的严格程度负责"。据此，AI worker 在 submit 时的完整性检查应该怎么设计？

Q11. 在项目 A 中，为了让 Router 和 Gate 也能核对任务版本，有人提议给它们加一个可选的任务协议参与开关，默认关闭、不影响其他人。你怎么评估？

Q12. 租约 TTL 已过期，同一会话的 owner 又调用了 touch。系统应该怎么处理执行权？

Q13. 在 ProjectBoard 里，要给一个任务开启"必须由第三方审查"的门，应该设置什么字段？agent 能不能关掉这个门？

Q14. RFC-3（状态收口）目前是什么状态？它描述的 task.interrupt 现在能用吗？

Q15. ProjectBoard 能否按某个历史时刻（asOf）查询任务当时的状态？

Q16. 项目 A 的任务协议目前是否已经从 Router、Gate 等非任务节点中拆出去？依据是什么？
