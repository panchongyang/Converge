# R-r2

## Q1

结论：不建议。ProjectBoard 的文档职责是"登记 + 定位 + 基线 + 状态 + 漂移观测"，正文归项目工作区、随项目走并上 git（E01，2026-11-01）。理由：看板的 `doc.put` 本质是拷贝，工作区原稿此后的修改不会同步，必然出现两份正文；离线查看和全文检索都可以在工作区文档上做，不需要把正文搬进看板。唯一例外是迁移完成前的内嵌文档按兼容结构只读（`docs/EXTERNAL-DOCS.md` §1），不改写历史。若确需索引，应建"引用 + 基线哈希 + 漂移状态"，而不是持有正文。

## Q2

结论：倾向直接做一次性显示迁移，不做"两档兼容"。依据 E02（2026-11-02）：当时项目未发布、只有本机 store，人类拍板"旧门直接降级，做显示迁移"，依据是项目阶段事实而非技术权衡；wire 名保留、显示迁移，回滚边界写进设计、不承诺双向兼容。前提：①项目确实未发布、无外部 v2 store；②迁移脚本可执行、可回滚并留记录；③回滚到旧代码时按单一旧语义处理。若出现外部 store，复议条件触发，需重新评估。

## Q3

结论：不应该。E03 明确"项目板不应当对证据的正确性负责，只对证据做诚实记录并能识别漂移"，推论是"跑命令啥的不应该是任务板的功能"。且 command/test 只是材料、不执行（`docs/design/test-implicit-contracts.md` 口径），与 RFC-4 旧描述"宿主执行"冲突，不能把旧实现当现行事实。开发者的测试与独立审查并不豁免。若需要核验，应由 auditor 自行执行并出报告，系统不代跑、不背书；"未漂移"也不等于"正确"。

## Q4

结论：拒绝在 block 里把 intent 标为 abandoned。E05：open intent 是 WAL，不是普通状态字段；副作用结果不明必须走 `task.interrupt` → `interrupted` → `task.reconcile`，不能借 block 清掉待对账状态。abandoned 只表示"这次尝试停止"，不表示没有副作用，且必须带 closeReason/outcome/sideEffects/actor/at。处理方式：block 拒绝并提示先 interrupt。原则是宁可保留不确定性，也不为满足 I6 把不确定性藏起来（RFC-3 文档仍标 Proposed，见 Q14）。

## Q5

结论：应按高优先治理，不以生产事故为前提。E07：变更安全性与长期可维护性是一等质量属性，架构/代码缺陷的累计成本（两轮返工、跨模型反复、逐案审查）本身即可定级。人类明确表示强烈不同意把架构缺陷或代码缺陷当成下等公民；AI 也承认此前把治理优先级过度绑定到生产事故证据，确实把门槛设偏了。边界：高优先不等于已证明整体失控，也不等于所有返工同源；证据确定度只决定结论能写多满，不替代优先级判断。

## Q6

结论：不算退化，但要看档案质量。E08：人类明确"记录真相是我做这个项目的第一目的"，为的是解决 AI 改来改去后谁都看不懂现状；AI 起初把它说成"从决定下一步退化成记录真相"，被改判成"档案系统的毛病"。评估看三件事：现状可解释、改动可追问、历史可重建，而不是"今天推得多快"。边界：记录本身可能噪声化或脱离代码，"只存过程"不等于可重建，所以"像 issue 中心"只是症状，不是结论。

## Q7

结论：不能跳过证据登记与事件日志。E11 的分层是"轻的是判定，不是记录"：AI 自主权、验收严格度、流程体验可分级可放宽；如实记录、不伪装已验证、历史可追溯不可削减，未验证完成也必须可见地记录。另外同一讨论中人类明确"先不加档位，我记住这个就行"，说明连"档位"本身都没有实施授权。可做的是交互层轻量化与默认视图收敛，而不是删事实层；否则记录会失真，违背 E08 的第一目的。

## Q8

结论：不成立，不应列为 ProjectBoard 的 P0。E12：人类指出这可能是不该在任务板实现的功能，任务板是建立在 DSH 上的应用，而不是日志系统；AI 承认缺口成立、责任归属并不成立。任务板记录证据与任务事实，不宣称独立、完整观测所有执行通道；reconcile 允许"未知"，也不等于验证全部外部动作可安全重做。缺口应在系统协作层解决，不能直接归为任务板缺陷；边界已冻结在 `evidence/incident-review-2026-11-03.md`。

## Q9

结论：不能。E13 的教训正是上一版只接通了 MCP：人类要求两边一致，并把 MCP 与 DSH 侧工具一致的约束写进文档；AI 承认确实漏了 DSH 的原生工具注册。面向 Agent 的业务能力默认 DSH 原生工具与 MCP 两侧同步交付，共享业务契约与守卫；入口身份与授权可不同，传输差异须显式记录。约束已写入 `docs/CONSTRAINTS.md` §2.1。MCP 侧测试通过只证明一侧可用。

## Q10

结论：必须分两侧设计，不能把"可追溯优先"当成对 AI 也放宽。E14：人类紧接着补了"当然我说的是对人来说，ai 确实得拦截"。AI worker 侧在 submit/reconcile 前必须拦截完整性错误与漂移并直接打回，verify 非 human 不可；人侧保留可追溯 + 合法出路，严格度可声明、可审计、可回退。硬底线只保留会导致记录失真的问题：missing/unreadable、command 失败、proof 错绑、路径逃逸。每个阻断都要留记录并给至少一条非豁免出路。

## Q11

结论：不应该加，即使"可选、默认关闭"也仍是耦合。E06：人类第四次强调任务协议已经耦合，应归为单独节点行为，不要扩展到多个节点，给全局加东西必须说明是否违背通用图；AI 承认做成"可选"仍然是耦合，之前处理错了。Router/Gate 应按公开输入处理普通载荷，任务内容/版本/凭据归任务节点；通用图是架构硬边界（README）。新增全局机制必须先给出通用图语义论证，而不是用"默认关闭"绕过。

## Q12

结论：不能凭 touch 恢复执行权。E16：同会话续租可以支持，但必须有明确的活性判据或有限宽限期；`touch` 也受 `maxRenewalsWithoutProgress` 限制，租约到期后按宽限回收，旧 fencing token 不得复活。人类还实证过"显式 renew 虽然返回拒绝，租约事实上已经延长"，说明 touch、renew、自动重新分配的活性与期限规则必须统一。"同会话"不等于"仍活着"，"能续租"与"执行权归属"是两件事。

## Q13

结论：字段是 `requiresAudit`；wire 名保留 `requiresHumanReview`/`gate:human`，用显示迁移表达"第三方审计门"（E02）。agent 不能关这个门：review 状态下 agent 不得开关门，human 是唯一能关门的人；agent 只能在非 review 状态开启（`project_task` 的 gate 也规定 agent 仅可在 review 外启用）。理由是项目未发布，所以旧门直接降级、不做两档兼容。注意"发布包零旧名"另立技术债，不等于门语义没迁移。

## Q14

## Q15
