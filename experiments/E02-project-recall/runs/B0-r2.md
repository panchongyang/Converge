## Q1

结论：不建议把正文同步进看板。ProjectBoard 的文档模型已经把正文放在工作区：外部文档以 locator + expectedMetaRev 登记，内联文档默认只读存档，put/link 会返回 inline-write-disabled。再同步一份正文就是第二个真相源，正文一改，看板副本与证据钉住的 Git 干净版本就对不上，离线看到的可能是过期内容。离线访问应指向注册文件或本地 checkout，看板只存链接、元数据与版本；要全文检索就索引工作区，不复制正文。依据：project_doc 工具契约。不确定：看板是否已有全文检索。

## Q2

## Q3

## Q5

## Q6

## Q7

结论：不建议砍事件日志，证据可以变轻但不能没有。可追溯是这套系统安全感的来源，事件日志是自动产生、近乎零成本的；砍掉它，任务状态就变成不可复核的断言。轻量档位的正确做法是降低登记成本：默认自动附带证据、允许 note 级证据、放宽 acceptance 条数，同时把"本任务为轻量档"显式写在任务上，让审查者知道自己在看什么。真要跳过，须由项目所有者显式开启并留痕。

## Q10

## Q12

结论：执行权应被收回，touch 不能复活旧租约。租约过期即失去 claim / begin / submit 的资格；同一会话身份不构成特权，所有权只认租约与 fencingToken。处理：拒绝 touch / renew 并返回 lease expired，要求重新 claim 拿到新的 fencingToken，之后的操作都带新 token；旧 token 一律 fencing 掉，避免两个执行者同时写。无进展时也受 renew 次数上限约束。依据：claim / begin / submit 需 live lease、fencing-stale 应重读而非强推的契约。
