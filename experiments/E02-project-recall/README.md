# E02 项目级认知重现（准备中）

## 目的

在真实项目材料上检验认知重现：材料存在表述模糊、记录过期、结论多次推翻、文档状态与实现不一致等问题。E01 在早期、整理良好的材料上已基本可行，差距只集中在状态与推理约束上；E02 检验差距是否在项目级材料上放大。

## 题源

`research/cognition-events-2026-11-15.md`（DS 提取的项目 P / 项目 A 认知事件，19 个事件 + 证据不足 + 未形成共识清单）。按用途分三类：

- 项目决策类（通用工程直觉会答错）：主体题源。
- 误读人话类（E09、E10、E15、E17）：属当场理解偏差，不作为重现题，留作另一实验。
- 过期与冲突类（文档状态与实现不一致）：重点题源，检验新会话是否把过期记录当成事实。

## 边界前提（用户确认）

项目 P 的看板（ProjectBoard 工具）只管事实。它的历史知识检索是事实检索，不是认知检索：可以辅助认知形成（从事实倒推），但不能作为认知延续能力。E02 中"现行文档 / 看板记录"作为事实材料组，与"结构化认知记录"组区分。

## 对照组

全部为 deepseek-flash（high）全新会话，同一题面（questions.md，16 题），每组 3 次。

| 组 | 材料 | 工具 |
|---|---|---|
| B0 | 无 | 无 |
| R | 认知事件报告（materials/R-events-report.md，嵌入 prompt） | 无 |
| D | 只读访问两个仓库的现行文档与代码（禁 evidence / archive / private / 会话存档 / git） | 读、搜索 |
| DR | D 的仓库访问 + R 的事件报告 | 读、搜索 |

D 组模拟真实新会话：自行查找依据，会自然碰到过期文档。R 组的事件报告本身也有时效：它写于 11-15 凌晨，对 E06 写的是"文档收口不代表代码整改完成"，而代码整改已于 11-14 完成（见 Q16）。
