# Converge

**让人与 AI 在协作中形成的共同理解，能跨会话保存、重现和修正。**

AI 已经能读到越来越长的历史，但读过历史不等于理解历史。新会话拿到聊天记录或总结后，能复述结论，却常常不知道当时为什么这样定、排除过哪些方案、什么条件变了才值得重新讨论。Converge 研究这个问题，并以**认知树**作为第一个产品方向：只记录协作中形成的判断、依据和取舍，不保存逐句对话。

## 为什么

长期协作中，一个复杂决定往往要经过多轮讨论才定下来。真正有价值的不只是结论，还有：

- **依据**：为什么这样定；
- **前提**：结论在什么条件下成立；
- **排除项**：哪些看似合理的方案已被否定，原因是什么；
- **复议条件**：什么变化会让被否定的方案重新值得考虑；
- **未决事项**：哪些问题还没有定论。

聊天记录里有这些信息，但淹没在大量往来中。总结和文档通常只保留"现在是什么"，被否定的方案和理由最先丢失。结论没了前提，新会话遇到相近但不同的情况时，要么机械套用，要么把早已排除的方案重新提出来。

后果包括：人需要反复解释背景；已经走过的弯路被重走；双方用同样的词，各自理解却不同，误以为已经对齐。

我们在自己的项目材料上做过两轮小规模实验（[E01](experiments/E01-cognition-recall/README.md)、[E02](experiments/E02-project-recall/results.md)），观察到：

- 只读仓库的新会话能说出决策结论，但说不出决策依赖的项目阶段前提；
- 关于"项目首要目的"的问题，无材料组和只读仓库组 3 次全部答偏，拿到决策记录的组 3 次全对；
- 只给各文档结论段落时，模型会自行推出原材料明确说过不成立的关系。

这些实验只用了单一模型，每组 3 次，结果由我们自己判读，没有盲评。它们说明问题确实存在，但不能说明问题有多普遍。

## 愿景

目标不是让 AI 记住更多，而是让协作中形成的理解能接着用下去。

设想中，一个新会话加入几周前开始的项目时，不需要人从头讲一遍背景。它能直接看到：哪些判断成立、由谁确认；哪些方案已被排除、为什么排除、什么条件下值得重新讨论；哪些问题仍然开放。人发现某条判断有误时，只需修正那一条并说明理由，依赖它的判断会被标出来，提示需要复查。设计判断与项目实际情况不一致时，冲突会被明确标记，而不是悄悄改掉其中一方。

日常维护由 AI 承担，人只在关键判断上确认或纠正。

**以上是方向，尚未被验证。**

## 认知树

认知树是实现这一方向的第一次尝试。核心设计如下：

**节点是判断，不是发言。** 每个节点记录"决定了什么"，而不是"谁说了什么"。我们早期参考过按对话分叉组织的树形对话产品，后来没有采用：它保存的是对话过程，组织和导航的负担都在人身上。

**剪枝保留理由和复活条件。** 被否定的分支不删除，同时记录剪除理由，以及什么条件下应当重新考虑。只记"已否定"的话，条件变化后没人知道该回头看。

**树为骨架，加少量有类型的引用边。** 纯树最初看起来就够了：从根到任一节点的路径就是推导链。但真实决策记录中有树表达不了的关系，例如两个无关决定共享同一个前提（"项目尚未发布"）。纯树只能复制节点，前提失效时容易漏改。通用图也不合适：节点有多条来路，阅读时难以复述；边没有类型，图会退化成乱线。最终方案是树加三种引用边：

| 引用边 | 回答的问题 |
| --- | --- |
| 依赖前提 | 某个前提失效时，哪些判断需要复查？ |
| 同类实例 | 相同的原则或失效模式以前出现过吗？ |
| 与事实冲突 | 这条判断与项目实际情况是否不一致？ |

新增边类型必须说明它回答了树和现有边都回答不了的问题。这一结构是讨论后的设计选择，原计划的纸面验证没有执行，推导过程记录在[认知表达结构](认知表达结构.md)。

**AI 可以修改，只有人能确认。** AI 可以新增判断、补充、勘误、剪枝和重新启用，变更保存即生效，但一律标记为"未经人确认"。已保存的原文不能直接覆盖，修正以补充、勘误或替代分支的形式存在，历史可以回查。

**只保存认知，不复述事实。** 实验中，只读决策记录的会话曾被记录里过期的进度信息误导。因此认知树只保存相对持久的目的、原则、理由和被否方案；"做到哪一步"之类的状态引用看板或仓库，两者不一致时标为冲突。

认知树的设计过程本身也用认知树记录，见[手工认知树 T1](认知树.md)。

## 快速开始

### 安装 DSH 插件

```bash
dsh plugin --profile web add dsh-cognition-tree
```

将 `web` 换成你实际使用的 Web profile。安装后启动或重启该 profile，刷新页面，在侧栏打开「认知树」。不需要克隆源码或加入 DSH 插件目录。安装指定版本可在包名后追加版本号，例如 `dsh-cognition-tree@0.4.9`。

请查看 [npm 对应版本](https://www.npmjs.com/package/dsh-cognition-tree)和[插件兼容性与安装说明](cognition-tree/adapters/dsh/README.md)。已发布的 `0.4.9` 仅声明支持 DSH `0.2.2-rc.1`。

### 从源码运行

开发和独立网页体验需要 Node.js 24、pnpm 12。

```bash
git clone https://github.com/panchongyang/Converge.git
cd Converge/cognition-tree
pnpm install --frozen-lockfile
```

**独立网页：**

```bash
pnpm --dir adapters/browser dev    # http://127.0.0.1:5317
```

打开后点击「导入样例 T1」，可以查看示例树，例如 T1.3.1"纯树"为什么被剪除。

**DSH 插件**（开发者从源码构建，普通用户无需执行）：

```bash
pnpm --dir adapters/dsh run build  # 输出到仓库根目录 .local-work/dsh-plugin/
```

构建、校验和使用边界见[插件说明](cognition-tree/adapters/dsh/README.md)。

## 范围

Converge 保存和修正共同认知。它不调度 agent 执行任务，也不为项目事实作背书。任务进度与验证证据归看板，执行编排归工作流工具。
